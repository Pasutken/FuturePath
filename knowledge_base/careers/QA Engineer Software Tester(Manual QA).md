# อาชีพ: QA Engineer / Software Tester (Manual QA)

## 1. บทบาทและหน้าที่ (Overview)

- **สรุปสั้นๆ ว่าอาชีพนี้ทำหน้าที่อะไร:** QA Engineer (Quality Assurance) หรือ Software Tester ทำหน้าที่เป็น "ด่านสุดท้ายในการตรวจสอบคุณภาพ" ของแอปพลิเคชันหรือเว็บไซต์ก่อนปล่อยให้ผู้ใช้งานจริง โดยมีเป้าหมายหลักคือการค้นหาข้อผิดพลาด (Bugs/Defects) ตรวจสอบว่าระบบทำงานได้ตรงตามความต้องการ (Requirements) ที่ตกลงกันไว้หรือไม่ และสร้างความมั่นใจว่าซอฟต์แวร์ที่ออกไปจะมีปัญหาน้อยที่สุด

- **ชีวิตประจำวัน (Day-to-day) ต้องเจอกับงานลักษณะไหน:** งานในแต่ละวันจะเริ่มต้นจากการอ่านเอกสารความต้องการ (Requirement/User Story) เพื่อนำมาวิเคราะห์และเขียน "กรณีทดสอบ" (Test Cases / Test Scenarios), จากนั้นคือการลงมือคลิกทดสอบระบบจำลองการใช้งานจริงแบบต่างๆ (Test Execution) ทั้งกรณีที่ใช้งานแบบปกติ (Happy Path) และกรณีที่พยายามทำให้ระบบพัง (Negative/Edge Cases), เมื่อเจอข้อผิดพลาดก็จะทำการบันทึกข้อมูลและขั้นตอนการเกิดปัญหาอย่างละเอียด (Bug Reporting) ลงในระบบจัดการ เช่น Jira เพื่อส่งให้ Developer แก้ไข และเมื่อแก้เสร็จก็ต้องกลับมาทดสอบซ้ำ (Re-test / Regression Test)

## 2. ทักษะที่จำเป็น (Required Skills)

- **Hard Skills:** - ทักษะการออกแบบการทดสอบ: การเขียน Test Plan, Test Case และ Test Scenario (เช่น Black-box Testing)
  - เครื่องมือบันทึกและติดตามงาน (Bug Tracking/Test Management Tools): Jira, Trello, Zephyr, TestRail
  - ความรู้ทางเทคนิคพื้นฐาน: การทดสอบ API เบื้องต้น (ด้วยเครื่องมืออย่าง Postman), การใช้คำสั่ง SQL เบื้องต้นเพื่อตรวจสอบความถูกต้องของข้อมูลในฐานข้อมูล (Database)
  - ความรู้เสริม: ความเข้าใจวงจรการพัฒนาซอฟต์แวร์ (SDLC) และการทำงานแบบ Agile/Scrum

- **Soft Skills:** - ความใส่ใจในรายละเอียดขั้นสุด (Extreme Attention to Detail) ช่างสังเกตและสามารถจับผิดจุดเล็กๆ ที่คนอื่นมองข้ามได้
  - ทักษะการสื่อสาร (Communication) เป็นทักษะที่สำคัญมากในการแจ้งปัญหาให้ Developer ทราบอย่างมีศิลปะ ชัดเจน ตรงไปตรงมา แต่ไม่สร้างความขัดแย้ง
  - การคิดวิเคราะห์แบบคาดการณ์ปัญหา (Critical & Analytical Thinking) เพื่อคิดหา Use Case แปลกๆ ที่ผู้ใช้อาจจะทำ
  - ความอดทน (Patience) เนื่องจากการทดสอบระบบเป็นงานที่ต้องทำซ้ำๆ และต้องเผชิญกับระบบที่ไม่สมบูรณ์ตลอดเวลา

## 3. เส้นทางการศึกษา (Educational Pathway)

- **สายตรง:** สาขาวิทยาการคอมพิวเตอร์ (Computer Science), วิศวกรรมซอฟต์แวร์ (Software Engineering) และเทคโนโลยีสารสนเทศ (IT) 

- **จบไม่ตรงสาย / อาชีพที่ไม่มีสาขาตรง:** เป็นหนึ่งในสายงาน Tech ที่ "เปิดกว้างสำหรับคนย้ายสาย (Career Switcher) มากที่สุด" ไม่จำเป็นต้องเขียนโค้ดเป็น ทักษะที่ต้องไปเรียนเพิ่ม (Top-up) คือหลักการทดสอบซอฟต์แวร์พื้นฐานและการใช้เครื่องมืออย่าง Jira สิ่งสำคัญที่สุดในการสมัครงานคือการทำ **Portfolio** ที่โชว์ความสามารถในการวิเคราะห์ระบบ เช่น การนำแอปพลิเคชันดังๆ ที่มีอยู่จริงมาเขียน Test Case หรือการลองหา Bug แล้วเขียนรายงาน (Bug Report) ที่มีข้อมูลครบถ้วนสมบูรณ์

## 4. โอกาสทางอาชีพและผลตอบแทน (Market & Salary)

- **ช่วงเงินเดือนสำหรับเด็กจบใหม่และคนมีประสบการณ์:** (อ้างอิงข้อมูลจริงจากรายงานตลาดแรงงาน Tech ในไทย เช่น Adecco, PRTR, Techsauce และ JobsDB)
  - **Junior (ประสบการณ์ 0-3 ปี):** ประมาณ 20,000 - 35,000 บาท/เดือน
  - **Mid-Level (ประสบการณ์ 3-5 ปี):** ประมาณ 35,000 - 60,000 บาท/เดือน
  - **Senior / QA Lead (ประสบการณ์ 5 ปีขึ้นไป):** ประมาณ 60,000 - 90,000+ บาท/เดือน (บางองค์กรอาจให้ได้ถึง 100,000 บาท แต่เพดานเงินเดือนของ Manual QA มักจะตันเร็วกว่าสายอื่นๆ ยกเว้นจะขึ้นเป็นระดับบริหาร Management)

- **แนวโน้มความต้องการในตลาด:** มีความต้องการสูงและคงที่อย่างต่อเนื่องตราบใดที่ยังมีการสร้างซอฟต์แวร์ใหม่ๆ ตำแหน่งนี้เป็นที่ต้องการในทุกบริษัท Tech อย่างไรก็ตาม **ข้อควรระวัง** คือในระยะยาว ตลาดแรงงานเริ่มคาดหวังให้ QA สามารถทำระบบอัตโนมัติ (Automation) ได้ด้วย ดังนั้น โอกาสเติบโตของ Manual QA แบบ 100% อาจเริ่มแคบลง หลายคนที่อยู่ในสายนี้จึงต้องวางแผนอัปสกิลเรียนรู้การเขียนโค้ดเพื่อขยับไปเป็น QA Automation หรือต่อยอดไปเป็น Business Analyst (BA) / Product Owner (PO) ในอนาคต
